## Нефункциональные требования

Нефункциональные требования определяют характеристики качества системы, включая требования к производительности, безопасности, надежности и используемым технологиям.

### Требования к производительности

Система должна обеспечивать достаточную производительность для проведения соревнований в режиме реального времени:

- данные турнирной таблицы должны обновляться в режиме реального времени;
- для снижения нагрузки на базу данных должно использоваться кэширование;
- время отклика API для операций чтения не должно превышать 200 мс при штатной нагрузке.

### Требования к безопасности

Система должна обеспечивать базовые механизмы защиты данных и контроля доступа:

- для аутентификации пользователей должны использоваться JWT-токены с возможностью их отзыва;
- доступ к функциям системы должен разграничиваться по ролям на уровне API и сервисного слоя;
- пароли пользователей должны храниться в зашифрованном виде с использованием соли (salt);
- система должна корректно обрабатывать исключительные ситуации, предоставляя информативные сообщения как пользователю, так и разработчику.

### Требования к надежности

Система должна обеспечивать устойчивость к ошибкам и корректную работу при одновременном взаимодействии нескольких пользователей:

- должна сохраняться целостность данных при параллельном доступе нескольких участников;
- в случае сбоев (например, при остановке или перезапуске контейнера) должно обеспечиваться корректное восстановление состояния системы.

### Требования к применяемым технологиям

При разработке системы должны использоваться следующие технологии:

- **бэкенд:** Python + FastAPI;
- **база данных:** PostgreSQL;
- **кэширование и механизм Pub/Sub:** Redis;
- **очереди сообщений:** RabbitMQ;
- **фронтенд:** React + Vite;
- **контейнеризация и развертывание:** Docker.
