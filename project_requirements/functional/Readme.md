## Функциональные требования

Система должна реализовывать ролевую модель доступа, включающую две основные роли: **участник** и **модератор**. Каждая из ролей обладает собственным набором функций и прав взаимодействия с системой.

### Функциональные требования роли «модератор»

Система должна обеспечивать следующие возможности для пользователя с ролью модератора:

- создание нового контеста с указанием названия, даты проведения, начального баланса для участников, максимального числа одновременно активных задач, а также настроек приватности (возможность отображения логов и турнирной таблицы);
- редактирование параметров существующего контеста;
- удаление контестов;
- настройку размеров игрового поля;
- редактирование содержимого ячеек игрового поля (карточек задач);
- регистрацию новых участников;
- просмотр списка зарегистрированных пользователей;
- изменение информации о пользователе (имя, баланс);
- удаление пользователей из системы.

### Функциональные требования роли «участник»

Система должна обеспечивать следующие возможности для пользователя с ролью участника:

- авторизацию в системе с использованием учетных данных, предоставленных модератором соревнования;
- просмотр игрового поля;
- приобретение карточек с задачами за игровые очки;
- просмотр турнирной таблицы в режиме реального времени при условии, что её отображение разрешено модератором;
- автоматическое обновление количества очков после проверки решения;
- учёт количества попыток при начислении очков;
- отправку ответов на приобретённые задачи.

### Прочие общие функциональные требования

Система должна обеспечивать выполнение следующих общих функций:

- автоматическую проверку правильности ответов на задачи;
- поддержку языка разметки **Markdown** для форматирования текста задач;
- поддержку различных тем оформления пользовательского интерфейса.
